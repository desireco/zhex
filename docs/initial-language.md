# Initial Zhex language contract

This contract defines the first Go interpreter and the executable examples used to validate it. Zhex is a Forth-inspired language with named values and checked composition. The initial implementation executes a checked syntax tree; it does not generate native code.

The runnable corpus is grouped into language basics and algorithms. The [Game of Life](../examples/life.zhex) evolves a finite array with a dead exterior; [edit distance](../examples/edit-distance.zhex) fills a dynamic-programming table using Unicode code-point comparisons. See [syntax-examples.md](syntax-examples.md) for their expected output and the rest of the corpus.

## Source and blocks

Source is valid UTF-8. Blocks use four spaces per indentation level; tabs outside strings and comments are rejected. Blank lines and `#` comments are ignored. Statements end at a newline except within an open `()`, `[]`, or `{}` expression, which may continue across lines; blank and comment-only lines inside the delimiters are allowed. Angle brackets in type syntax do not open a continuation, and trailing commas are not accepted. Syntax nesting and expression-tree depth are limited to 256 to report overly deep source as a language error.

Names use ASCII letters, digits, and underscores, starting with a letter or underscore. Hyphen-separated name segments beginning with a letter or underscore are allowed, as in `is-palindrome`. Dots qualify operation names: a dot names the type or module that owns the word. A dot after a record value reads a field, as in `customer.name`; field paths may be nested. A leading underscore marks a word or type module-private (see Modules). Consequently `a-b` is a name, while `a - b` is subtraction: use spaces around subtraction between names. Keywords cannot be binding or word names; `use`, `choice`, `match`, and `case` are among them. Strings use double quotes and Go-style escapes, and must decode to valid UTF-8.

## Values and expressions

The built-in value types are `Int`, `Bool`, `String`, and `Unit`, plus the `Buffer` and `File` resource types described with the standard operations. Named record types contain typed fields; named choice types contain fixed alternatives. `List<T>` and `Array<T>` are homogeneous mutable collection types; `Map<K, V>` stores values under `String`, `Int`, or `Bool` keys and is traversed in insertion order. Map lookup returns the built-in `Option<V>` choice. Selected built-ins return `Result<T, E>` values. A user word may declare that result type explicitly, or infer it when an escaping `try` can fail; supported error families are `InputError`, `ParseError`, `FileError`, `BufferError`, and common `Error`. Result values must be handled or propagated immediately. `Int` is a signed 64-bit integer. Literals include decimal integers, `true`, `false`, strings, homogeneous list literals such as `[1, 2, 3]`, and nonempty map literals such as `{"Ada": 10}`. Negative integer literals include the full signed range. Overflow is a language error; division and remainder by zero are errors. Division truncates toward zero; remainder has the dividend's sign. The minimum integer divided by `-1` overflows; its remainder modulo `-1` is zero.

Precedence, from lowest to highest: `or`, `and`, `== !=`, `< <= > >=`, `+ -`, `* / %`, unary `-`/`not`, calls, record-field and collection-index access, and postfix `try`. Binary operators associate left. Operands, call arguments, index expressions, and assigned values evaluate left to right; `and` and `or` short-circuit. Arithmetic requires integers, except `+` also concatenates two strings. Ordering requires integers. Equality compares matching `Int`, `Bool`, or `String` values. There are no implicit conversions.

`let name = expression` creates an immutable binding. `var name = expression` allows assignment with `name = expression`, preserving its inferred type. Either binding can include an explicit type annotation: `let name: Type = expression` or `var name: Type = expression`. The checker requires the expression's type to match the annotation. Bindings have lexical block scope; duplicates in one scope are errors. Inner scopes can shadow outer names. Parameters are immutable.

## Records and named types

`type Customer = record` declares a nominal record type followed by indented `field: Type` declarations. A record value is constructed positionally in declaration order, as `Customer("Ada", 36)`, or with named fields, as `Customer(age: 36, name: "Ada")`; its immutable fields are read with `customer.name`. Fields can contain shared mutable collections. A record declaration is not a type alias. See [records and named types](../site/src/content/docs/records.md).

## Choices and matching

`type Status = choice` declares a nominal choice type followed by indented alternatives, such as `Pending` or `Failed(message: String)`. Nullary alternatives are constructed as `Status.Pending`; payload alternatives use positional values in declaration order, as `Status.Failed("offline")`. A choice can declare one type parameter, such as `Maybe<T>`; generic words and records are not supported. See [choices and matching](../site/src/content/docs/choices.md).

`match value` checks each alternative in an indented `case` arm. Cases bind payloads immutably and locally; `_` in a payload position ignores that field. Cover every alternative once, or put one final `case _` to handle what remains. A redundant default after all variants are covered, duplicate or missing cases, and cases after a wildcard are checker errors. Match evaluates its subject once and can be a statement, a word's final expression, or the whole right-hand side of a `let` or `var`. All value-producing arms must agree; a non-returning branch such as `console.exit` may participate without supplying a value. Choice payloads cannot contain `Result` values; storing a caught concrete error in an `Error` payload requires explicit `error.wrap`. Choices cannot be compared or printed directly. Guards, nested patterns, and aliases are not supported.

## Lists and arrays

`List<T>` is a homogeneous growable list; `Array<T>` is a homogeneous rectangular array with runtime shape. Nonempty list literals infer a common element type; empty list literals and `list.new()` require an expected `List<T>` type. Array dimensions are a `List<Int>` and are supplied to `array.new(dimensions, fill)`. Nested list literals do not implicitly convert to arrays. Both collection types share mutable storage across assignments and parameters. `let` fixes a binding name, not the referenced collection.

`Map<K, V>` is a shared mutable mapping that preserves key insertion order. Nonempty literals infer their key/value types; an empty literal needs an expected map type. Keys are `String`, `Int`, or `Bool` constants in literals. `map[key]` returns `Option<V>` without `try`, while `map[key] = value` sets an entry and returns `Unit`. `map.put`, `map.remove`, `map.into`, `map.contains`, and `map.length` provide named operations. Map iteration visits entries in insertion order. Mutating a map while it is actively traversed raises a runtime `collection-iterating` diagnostic before mutation; this guard also applies through aliases and to no-op mutations. See [maps](../site/src/content/docs/maps.md).

`list.length` returns an `Int`; plain `list.append` returns `Unit`. Collection elements use zero-based brackets: `values[i]` reads one list element and `grid[i, j]` reads an array cell. Plain reads and collection creation or growth return ordinary values and produce runtime diagnostics for invalid operations. Apply `try` or `catch` directly to a read, `array.new`, `array.resize`, or `list.append` to handle that operation as a Result; nested argument failures remain separate. Plain indexed assignment such as `values[i] = value` returns `Unit`, with invalid rank, bounds, or active-iteration mutation producing a runtime diagnostic. Parenthesize the assignment, as `(values[i] = value)`, to get `Result<Unit, Error>` for `try` propagation or local `catch`. `array.rank`, `array.length`, and `array.shape` inspect dimensions; `array.resize` changes dimensions without changing rank and preserves values at overlapping coordinates. Array rank is 2 through 32, extents are nonnegative, and list/array size is limited to 1,000,000 elements. See [lists and arrays](../site/src/content/docs/collections.md) for exact operations, error codes, and mutation behavior.

## Words and composition

`word name(parameter: Type, ...)` introduces a top-level definition followed by an indented body; an optional `-> Type` annotation can state its success type. Parameter annotations can also be omitted when the body and calls in the same program determine one concrete type. A parameter left unconstrained needs an annotation; conflicting calls are type errors, and `Result` is not a valid word parameter type. A recursive cycle without a concrete type anchor, empty list, or nullary `Option.None` result needs an explicit return annotation. A word may declare `Result<T, E>` directly; otherwise, if a `try` can propagate a built-in error, the checker infers the effective `Result<T, E>` signature and wraps successful values once at the word boundary. A pure word keeps its inferred or declared success type. Definitions may call other definitions, including forward references. The final statement supplies the word result; bindings, assignments, loops, and empty blocks have type `Unit`. Words do not capture top-level local bindings. Recursive calls have a runtime depth limit of 256.

Call a word with the existing parenthesized form `name(arguments)` or, for a simple call at a complete expression boundary, the comma-separated form `name argument, argument`. The latter can be a complete statement, binding or assignment right-hand side, final word value, or flow step; whitespace alone does not separate arguments. `print 1 + 1` passes the arithmetic result to `print`. Keep nested calls parenthesized (`print(add(1, 2))`) and use parentheses for ambiguous first arguments such as a negative number or list literal. Existing indexing such as `values [0]` remains indexing. A `flow expression` block passes the current value to each step as its first argument; a call-shaped step can add arguments, as in `add 3` (equivalent to `add(current, 3)`). Additional arguments evaluate once from left to right after the current value. Mark fallible steps or arguments with postfix `try`; a bare fallible step is rejected. The final step's value is the flow's result. An `if`, `match`, or `flow` block can supply the entire right-hand side of a `let`, `var`, or assignment; the block's final value is used. These block forms are not general nested expressions or call arguments. Calls are resolved and their input/output types checked before execution.
See the [calls and defaults guide](../site/src/content/docs/calls.md) for runnable source and the boundaries between short and parenthesized forms.

For a user word or a supported built-in, put `_` in a standalone argument slot to create a function value with that slot left open: `let plus-five = add _, 5`. Each hole becomes a required function parameter in left-to-right order; omitting an argument without a hole is still an arity error, not automatic currying. Supplied arguments are evaluated once from left to right and captured when the partial is created. Capturing a scalar stores its current value, while capturing a mutable collection keeps its shared reference. Omitted default arguments stay deferred and are evaluated on each invocation. A function type such as `(Int) -> Int` can annotate a partial explicitly; overloaded built-ins need an annotation or sufficient call-site constraints to resolve their type. A partial of a fallible target has a `Result` return type: its error happens on invocation and must be handled there, while an explicitly supplied argument's `try` runs at creation. Function values can be called, passed to or returned from words, stored in supported aggregates, or used as flow steps. They cannot be printed, compared directly, or encoded as JSON. Special targets such as constructors, loop-only operations, reporter registration, and non-returning operations are not partially applied.

## Results, propagation, and recovery

The built-in error families are `InputError`, `ParseError`, `FileError`, and `BufferError`; `Error` is a common family for application-created or explicitly converted errors. Built-in operations declare their Result families; user words can use an explicit `Result<Int, ParseError>` signature or infer one from escaping `try` expressions. There are no user-defined error types.

Postfix `try` unwraps a successful Result. A failure propagates to the caller; the checker includes the escaping family in a user word's effective signature, and every caller must use `try` or `catch`. Forward calls, recursion, and imported words contribute to inference. Multiple uncaught error families in one word are rejected; catch one or explicitly convert it with `error.wrap` to common `Error`. Runtime faults such as overflow and division by zero are not inferred as Result effects. At the program boundary, top-level `try` keeps the existing behavior: the unhandled error is reported as a source-located diagnostic and the run exits nonzero.

For inferred user words, an ordinary success value is wrapped once by the checker. If a handler or early exit must construct a failure explicitly, `err(error)` returns it from the word; an inferred `-> T` signature can infer that error family too. An explicit `Result<T, E>` signature remains available and uses `ok(value)` for success and `err(error)` for failure without a second success wrap. `error.new(code, message)` creates a cause-less common `Error` at that call site. `error.wrap(code, message, cause)` creates a common `Error` that retains the cause and its original origin. Error families do not widen implicitly: a caught concrete error may be passed directly to built-in `error.*` operations, but must be wrapped before passing to a user-defined word that accepts `Error` or storing/returning it in an `Error` field or collection. Pass a wrapped error directly in a named call; a flow cannot pass an Error value to a user-defined step, even when wrapped.

`catch` follows a Result-producing expression as a statement and may bind the error: `let value = operation() catch problem` followed by an indented handler. The handler runs only on failure and its final statement must have the Result's success type. It may use `return err(...)` to exit early from a fallible word. `catch` does not intercept runtime faults such as overflow or division by zero.

A Result-producing expression cannot be discarded. A bare fallible call is rejected. A Result stored by `let` must be handled immediately: the next statement in the same block must be exactly `pending try` or `pending catch ...`, either as a standalone expression or as the full right-hand side of a new `let`. It cannot be put in `var`, aliased, passed to another word, or handled later or conditionally. The REPL applies the same rule to each entry.

Errors can be inspected with `error.code`, `error.message`, `error.operation`, `error.file`, `error.line`, `error.column`, and `error.detail`. `error.has-cause` checks for a cause; `error.cause` returns a Result that fails with `error-no-cause` when absent. Error bindings are immutable. See [diagnostics and tracing](../site/src/content/docs/diagnostics.md) for the exact signatures.

An application may set a named reporter using `error.set-reporter(report-word)` at top level before fallible calls; the word must have signature `(Error) -> Unit`. `error.report(problem)` explicitly reports a failure that the application handled. A failure escaping the program invokes the reporter automatically once before the regular diagnostic. Intermediate propagation does not notify the reporter. Reporter failures do not replace the original result or runtime error, and `console.exit` or `console.fail` inside the reporter cannot override the original outcome. There is no external reporting destination by default. Codes supplied to `error.new` and `error.wrap` are application-owned and are not entries in the built-in diagnostic catalog.

`console.exit(status)` terminates execution with a deliberate status from `0` through `255` and can be used as a `catch` fallback instead of producing a value. A valid exit is not a diagnostic and does not call the automatic reporter. An out-of-range status raises the source-located `console-exit-status` runtime diagnostic, which can be reported. `console.fail(message)` writes the message and a newline to standard error, then terminates with status `1`; it is also a valid `catch` fallback and does not call the automatic reporter. These exits close active `file.lines` streams; files opened explicitly with `file.open` remain the program's responsibility to close with `file.close`. If either operation runs inside a reporter, it cannot replace the original outcome. In the REPL, `console.exit` and `console.fail` end the entire process.

## Modules

A program splits across files. `use math` at the top level of a file imports the module named `math` by loading the sibling `math.zhex` next to the importing file — each file's own imports resolve beside it. A module that cannot be loaded is a `use-missing` error naming the searched path. `use` is a keyword and is allowed only at a file's top level (`use-location`); a repeated `use` of the same module is a no-op.

An imported word is called qualified, as in `math.gcd(a, b)` or a flow step. Inside its own file a module's words call each other bare, and they cannot see the importing file's words. A word or named type whose name starts with an underscore is private to its module: usable only inside its own file, never suggested outside it, and reached from another file only as a `private-use` error. Public word signatures, record fields, and choice payloads cannot expose a private type, including through `List`, `Array`, `Map`, or `Result`. Imported choice constructors and match cases use qualified names such as `model.Status.Pending`. A module's own imports stay private to it — naming a module directly is the only way to see its words and types — and two modules never collide, even when their names share names. Duplicate word and type names are detected per file, and an entry file cannot redefine an adopted qualified name.

Module names `text`, `int`, `buffer`, `file`, `console`, `error`, `list`, `array`, `map`, and `json` are reserved (`use-reserved`); those prefixes belong to standard operations. The built-in `Option` type and its `Some`/`None` constructors are reserved names, but `Option` is not itself a reserved module name. An imported file may declare words and types — top-level statements are a `module-body` error — and import cycles are `use-cycle` errors spelling the files in the cycle. Every loaded module checks before the file that imports it, so dependencies report first, and module errors annotate the module's own source at check time and at runtime.

The REPL resolves `use` against the working directory and adopts each named module for the rest of the session; its qualified words then persist across entries and list under `words`. The REPL also preloads the ordinary word `bye() -> Unit`, which exits with status 0, appears in `words`, follows normal redefinition rules, and is unavailable in source files. `words` displays effective inferred parameter, return, and Result signatures. An inferred parameter must be determined within its entry; later entries cannot add constraints to an already checked definition. Redefining a word with an incompatible effective signature is rejected without replacing the previous word or adopting other definitions from that entry. The two-file [modules example](../examples/modules/main.zhex) shows the shape: `main.zhex` runs the program and `math.zhex` beside it supplies the words, one of them underscore-private.

## Decisions and iteration

`if condition`, optional `elif condition` blocks, and optional `else` select a branch. Conditions must be `Bool`. Branch result types must match; a missing `else` supplies `Unit`. Each branch has its own lexical scope.

`for name in range(start, end)` iterates upward over integers with an exclusive end, without building a list. Bounds evaluate once. If `start >= end`, the loop is empty. The iteration binding is immutable and each iteration has its own block scope. The loop result is `Unit`.

`for line in file.lines(path)` iterates over the lines of a UTF-8 text file without holding the whole file. The path is a `String` evaluated once; each line is chomped like `read-line` (one trailing LF and an immediately preceding CR removed) and bound as an immutable `String` with its own block scope. An empty file runs no iterations; a final line without its newline still runs. The file is closed when the loop finishes and on every exit, including a failure in the loop body. A path that cannot be opened is a `file-open` error; content that is not valid UTF-8 is a `file-utf8` error. `range` and `file.lines` exist only in these loop syntaxes.

`for value in collection` traverses a list or array. Optional dual bindings are `for index, value in list` and `for coordinates, value in array`; indices are zero-based `Int`s, while array coordinates are a fresh `List<Int>` for each cell. Maps allow `for value in map` or `for key, value in map` and preserve insertion order. The collection expression is evaluated once. Lists visit increasing indices and arrays visit in row-major order, with the last coordinate changing fastest. Empty collections run no iterations. Mutating an actively traversed list or array fails before changing it; plain indexed assignment produces a runtime diagnostic, while parenthesized checked assignment and other checked mutations can return `collection-iterating` for `try` or `catch`. An actively traversed map rejects mutation with a runtime diagnostic before changing it. Guards are released on normal completion and all exits. See [collection iteration](../site/src/content/docs/iteration.md) and [maps](../site/src/content/docs/maps.md).

## Standard operations and console input

The initial predeclared operations are `print`, `int.to-string`, `text.reverse`, `read-line`, and `text.to-int`. `print` accepts one `Int`, `Bool`, or `String`, writes it followed by a newline, and returns `Unit`. Boolean text is `true` or `false`. `int.to-string` takes an integer. `text.reverse` takes a string and reverses Unicode code points without normalization. A dot qualifies an operation with its owner type or module; a dot after a record value selects a field. The original core operations include bare names such as `print` and `read-line`.

The `text` words operate on `String` values, Unicode-safe by code point. `text.length` counts code points. `text.line-count` counts lines — empty text is `0`, and a trailing newline does not add a line. `text.word-count` splits on Unicode whitespace. `text.upper` and `text.lower` map case; `text.trim` removes surrounding Unicode whitespace. `text.contains(text, part)` reports whether `part` occurs. `text.index-of(text, part)` returns the code-point position of the first occurrence, or `-1` when absent. `text.slice(text, start, end)` returns the code points from `start` up to `end`; bounds below zero and past the length clamp, and `start >= end` yields the empty string. `text.replace(text, old, new)` rewrites every occurrence of `old` with `new` — literally, not as a pattern; empty `old` is a `replace-empty` error, a bug signal rather than a recoverable case.

## Type aliases and field defaults

`type Names = alias List<String>` creates a transparent alternate name, with no constructor or new identity. Aliases follow module privacy and cannot hide Result obligations; generic alias declarations and cycles are rejected.

Record fields can have defaults, such as `retries: Int = 3`. Required fields precede defaulted fields, and constructors may omit trailing defaults. Constructors accept either positional arguments in field order or named arguments in any field order; a call cannot mix the forms. Named constructor arguments are specific to records, not words, built-ins, or choice alternatives. Supplied arguments run once in source order, then omitted defaults evaluate in field order in the declaring module, afresh for every construction. Defaults cannot access caller bindings or fields and cannot propagate Result failures. Explicitly supplied collections retain their sharing.

## Word parameter defaults

Word parameters can also have defaults: `word greet(name = "Ada")`. Required parameters must come first, and calls remain positional; only trailing defaulted parameters may be omitted. A default can determine an otherwise omitted parameter type. Supplied arguments evaluate once from left to right, followed by omitted defaults in parameter order. Defaults are evaluated lazily in the declaring module, cannot refer to parameters, globals, or caller bindings, and cannot let a `Result` failure escape. Each call evaluates omitted defaults afresh, including mutable defaults. In the REPL, `words` shows a default as `= ...`. Compatible redefinitions affect new entries; checked callers continue to use the earlier word and defaults.

## Dates and time zones

`Date`, `Time`, `Duration`, `Instant`, `TimeZone`, and `ZonedDateTime` are distinct built-in types. Numeric constructors and calendar/elapsed operations use ordinary values and report invalid components or range overflow as runtime diagnostics. Text parsing and IANA time-zone lookup return Results. Local time resolution chooses the earlier occurrence in an overlap and shifts forward by the actual gap when a time does not exist. Calendar days preserve wall time, while elapsed durations preserve their length. Years 1 through 9999 are supported; use explicit formatting. See [dates and time zones](../site/src/content/docs/temporal.md) for operations and exact syntax.

## JSON

`json.decode(raw, defaults)` returns `Result<T, Error>` where `T` is the defaults value's type. Missing record fields use corresponding values from `defaults`; unknown or duplicate fields and supplied values of the wrong type fail rather than falling back. `json.encode(value)` returns a compact JSON string as `Result<String, Error>`. The codec supports `Int`, `Bool`, `String`, records, `List<T>`, `Map<String, T>`, and `Option<T>` in nested combinations, except directly nested `Option<Option<T>>`. JSON `null` decodes as `Option.None`; omitting an Option field uses its default. Present lists and maps replace defaults, and mutable defaults are freshly copied for each decoded result.

Integer JSON numbers must be integer-form signed 64-bit values; decimal and exponent forms are rejected. Arrays, resources, Results, non-Option choices, and maps with non-string keys are unsupported. Errors include `json-syntax`, `json-type`, `json-field`, `json-range`, and `json-depth`; `error.detail(problem, "path")` supplies a JSON Pointer to the offending value. See [the JSON guide](../site/src/content/docs/json.md) for exact details.

`Buffer` is a growable list of `String` lines for building text incrementally. `buffer.new()` creates an empty buffer; `buffer.add-line(b, line)` appends a line and returns `Unit`; `buffer.line-count(b)` returns the number of lines; `buffer.line(b, i)` returns `Result<String, BufferError>`, failing `buffer-range` on an index outside the lines; `buffer.set-line(b, i, line)` returns `Result<Unit, BufferError>` under the same rule; `buffer.to-text(b)` joins the lines with newlines. `let` binds the name, not a copy, so a second name observes the same buffer. Buffers are excluded from `==` and `!=`, and `print` rejects a `Buffer` with a hint to convert through `buffer.to-text`.

Files read through two layers. The whole-file layer returns everything at once: `file.read-all(path)` yields `Result<String, FileError>`, and `file.read-lines(path)` yields `Result<Buffer, FileError>` with every line chomped. The streaming layer holds an open handle: `file.open(path)` yields `Result<File, FileError>`; `file.read-line(f)` yields the next chomped line as `Result<String, FileError>`, and reaching the end of file fails inside the `Result`; `file.close(f)` releases the handle, returns `Unit`, and is safe to call twice, while reading from a closed file fails. The `for line in file.lines(path)` loop covers the streaming case with the close guaranteed on every exit. Files are read as UTF-8 and validated at the boundary; a path that cannot be opened fails `file-open`, naming the path and the operating system's reason. A `File` is excluded from `==` and `!=`, and `print` rejects it.

`read-line(prompt)` takes a string prompt and returns `Result<String, InputError>` from one line of standard input. `text.to-int(text)` is the inverse of `int.to-string`: it parses a signed 64-bit decimal, trimming surrounding whitespace, and returns `Result<Int, ParseError>`. Program arguments arrive the same way: `zhex run <file> [args...]` forwards non-option arguments after the source file to the program; `--trace` and `--report=text|json` remain interpreter options wherever they occur, and other `--` options are rejected, `console.args-count()` returns how many there are, and `console.arg(i)` returns `Result<String, InputError>`, failing `argument-missing` on an index outside the arguments. Results cannot be printed, compared, or used as ordinary values; handle them with `try` or `catch`.

The [example guide](syntax-examples.md) defines line endings, integer parsing, EOF, invalid UTF-8, prompts, and supported input domains. Prompts are written and flushed before reading. Redirected input is supported. Runtime input/output errors include source locations and exit nonzero; previous output remains visible. The interpreter checks the whole program, including unused word bodies, before any input or output occurs.

## Commands and validation

Run `go run ./cmd/zhex run examples/fibonacci.zhex`, or build with `go build -o bin/zhex ./cmd/zhex` and run `./bin/zhex run examples/fibonacci.zhex`. The runner requires a source file; `zhex repl [--trace]` instead starts an interactive session whose words and values persist across entries — a blank line submits an entry when no delimiter is open, bare expressions echo their value, errors print a diagnostic without ending the session, and `words` lists signatures.

Run `go test ./...` for the executable language cases and CLI tests. Run `go vet ./...` for Go checks. The [test catalog](tests.md) maps syntax and behavior to those tests. Generic words and records, broader resource scopes, and native compilation remain later work.
