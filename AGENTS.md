# Zhex agent guide

Zhex is a Forth-inspired language with named values and checked composition. A Go interpreter executes a checked syntax tree; there is no native backend yet. Write small words, name important values, and let the checker catch mistakes before anything runs.

## Repository map

- `internal/lang` — the language implementation: `syntax.go`, `lexer.go`, `parser.go`, `check.go`, `eval.go`, `host.go`, `session.go`. Tests in that directory are the executable specification (see `docs/tests.md`).
- `cmd/zhex` — the CLI: `go run ./cmd/zhex run <file>`; `go run ./cmd/zhex compile <file.zhex> [-o <out.wasm>] [--target=browser|wasi]` checks the same program and assembles a WebAssembly module (`docs/wasm-plan.md`).
- `examples/*.zhex` — validated example corpus split on the website into language basics and algorithms (including simple calls, word defaults, explicit partials, Game of Life, and edit distance), plus the two-file programs under `modules/` (the math library, the pure-Zhex md Markdown report module, and the html composition module with its escaped-unless-raw contract). The website executes every registered example at build time; a broken example fails the build. `examples/demos/` holds the demos-page programs — demoSpecs manifest rows in tools/site-data (build-time oracle plus browser wasm artifact), not examples-page cards — four Game of Life runs: `demos/life.zhex` (the 25-by-25 patterns intro), `demos/gun.zhex` (a Gosper glider gun streaming gliders across a 54-by-54 board), `demos/acorn.zhex` (the seven-cell methuselah's first 150 generations on a 60-by-60 board), and `demos/diehard.zhex` (the methuselah that goes extinct after exactly 130 generations on a 24-by-24 board).
- Standard-library proposals and the current inventory live in `docs/standard-library-plan.md`; proposed signatures there are not implemented APIs. Stories #57–64 are approved for one-by-one review and triaged to Todo; review and claim a selected story before implementation.
- `docs/` — the language contract (`initial-language.md`), getting-started guide, research notes, and the versioning policy (`versioning.md`): no version numbers, tags, or CHANGELOG before the standard library's 0.1 release.
- `site/` + `tools/site-data` — Astro pages and build-time executable example data; the build's `-wasm` pass compiles the in-subset examples to browser wasm beside the data; `site/design/` ships the design system verbatim — a change introducing a new UI element updates the design system in the same change.
- `editors/` — syntax highlighting for Vim/Neovim, VS Code, and Zed.
- `ROADMAP.md` and the public project board (github.com/users/desireco/projects/8) track the same work; keep them in sync.

## Writing correct Zhex

- Blocks use four spaces per indentation level; tabs outside strings and comments are rejected. `#` starts a comment; contiguous full-line `##` comments at column 1 directly above a `word` declaration become that word's doc — one optional leading space is stripped per line, a blank or plain `#` line between the block and `word` detaches it, and `##` anywhere else stays a plain comment. Statements end at a newline except inside open `()`, `[]`, and `{}` delimiters, which allow multiline expressions and blank/comment lines; trailing commas are rejected. Angle brackets in types do not continue a line.
- Bindings: `let name = expr` is immutable; `var name = expr` allows later `name = expr`. Either may include an explicit annotation (`let count: Int = 3`). An `if`, `match`, or `flow` block can be the entire right-hand side of a binding or assignment; its final value supplies the result. Types include `Int` (signed 64-bit), `Bool`, `String`, `Unit`, nominal records and one-parameter choices, `List<T>`, `Array<T>`, `Map<K, V>`, built-in `Option<T>`, the host-predeclared recursive `Json` tree type, `Date`, `Time`, `Duration`, `Instant`, `TimeZone`, `ZonedDateTime`, and the `Buffer` and `File` resource types. Fallible input and parsing built-ins return `Result<T, E>` with `InputError`, `ParseError`, `FileError`, `BufferError`, or the common `Error` family; user words infer an effective Result signature when a `try` can escape. There are no implicit conversions, generic words, or generic records. One exception exists — the string-context Int exception: `+` concatenates when exactly one operand is `Int` and the other is `String` (the Int renders as `int.to-string` does, chains associate left to right, and two `Int` operands still add numerically), and `print` accepts an `Int` directly. `Bool` and every other type stay strict in these positions, and no other position converts. Transparent aliases use `type Names = alias List<String>`. Record fields may have defaults (`retries: Int = 3`); required fields come first and constructors may omit trailing defaults. Record constructors are positional or all-named (not mixed); named arguments are only for records.
- Words: `word name(parameters)` or `word name parameter, parameter` may annotate each parameter and optionally add `-> Type`, followed by an indented body. A `##` doc block directly above the declaration documents the word (user words only, module words included): `words` prints it indented beneath the signature, a redefinition replaces it, and a doc-less redefinition clears it. Parameter annotations may be omitted when the body and calls in the same program determine one concrete type; unresolved parameters need annotations, conflicting calls are type errors, and `Result` is never a parameter type. Trailing parameters may have defaults (`name: String = "Ada"`); required parameters come first, calls remain positional, and only trailing defaults may be omitted. Defaults are evaluated lazily in declaring-module scope after supplied arguments, in parameter order, and afresh on each call; they cannot reference parameters, globals, or caller bindings or let a `Result` escape. `words` displays them as `= ...`. Built-ins may declare trailing constant defaults — `file.write(contents, path, append = false)` is the first; call sites may omit them, and omitted defaults stay deferred for partials, matching user words. If the return annotation is omitted, the body must determine one concrete success type; an ambiguous recursive cycle or empty collection result needs an explicit return annotation. The inferred or declared type is the success type; a `try` that can escape infers an effective `Result<Type, Family>` signature, and successful values are wrapped once. Calls may use `name(args)` or a comma-separated short form at a complete expression boundary; nesting and ambiguous arguments keep parentheses. A callable partial uses standalone `_` holes as required function parameters; captured arguments evaluate once in source order at creation, and omitted defaults stay deferred. Supported built-ins can be partially applied; overloaded built-ins need an annotation or sufficient call-site constraints, and constructors, loop-only built-ins, reporter registration, and non-returning built-ins cannot. Fallible function results propagate when invoked and require `try` or `catch`; an explicit argument `try` runs during capture. Function values can be stored or passed in supported positions, but cannot be printed, compared directly, or encoded as JSON. This does not imply automatic currying. In flows, the current value is the first argument and call-shaped steps can add arguments; function values can also be flow steps. Mark each fallible caller with postfix `try`. Words may be recursive (runtime depth limit 256).
- Arithmetic: `+ - * / %` on integers; `+` also concatenates two strings, or a `String` with an `Int` (the string-context Int exception — the Int renders as `int.to-string` does, and two `Int` operands still add numerically). Division truncates toward zero; division or remainder by zero and integer overflow are language errors.
- Comparisons: `< <= > >=` require integers; `==` and `!=` compare matching `Int`, `Bool`, or `String` values. `and`/`or` short-circuit. Precedence, low to high: `or`, `and`, `== !=`, `< <= > >=`, `+ -`, `* / %`, unary `-`/`not`, calls, postfix `try`.
- Branching: `if`, optional `elif`, optional `else`. Conditions must be `Bool`; branch result types must match. A `match` selects a declared choice alternative and must cover every alternative or end with `case _`; choice payloads cannot hide Results or caught concrete errors.
- Loops: `for n in range(start, end)` — exclusive end, empty when `start >= end`; `for line in file.stream(path)` streams a file's chomped lines and always closes the file. `for value in list|array|map` and dual bindings traverse collection entries; map traversal follows insertion order and mutation of the active map raises a runtime diagnostic. List/array indexed writes during active traversal also fail before mutation: plain writes diagnose at runtime, while parenthesized checked writes can be caught. These forms exist only in loop syntax. `while condition` repeats an indented body while its `Bool` condition holds, evaluated before each pass; it is a statement of type `Unit`, cannot be the right-hand side of a binding or assignment, has no `break`/`continue`, and may run forever by design — no iteration limit applies.
- Flows: `flow <expression>` evaluates the expression, then passes its value to each step as the first argument; a call-shaped step may supply additional arguments, evaluated once from left to right. The last result is the flow's result. Mark each fallible step or argument with `try`; the seed can be any expression, including a computed call or a fallible call marked `try`. Connect one-pass transformations directly; name values when reused or when a name clarifies state.
- Result handling: Input and parsing operations return explicit `Result<T, Family>` types. List/array reads, `array.new`, `list.append`, `array.resize`, and `file.exists` return ordinary values with runtime diagnostics for invalid operations; apply `try` or `catch` directly to select a checked Result for that operation. User word parameters cannot have Result types. For user words, an inferred or annotated return type is the success type; a `try` that can escape infers the effective `Result` family, with one success wrap at the word boundary. A pure word keeps its inferred or declared success type. Postfix `try` unwraps success and propagates to each caller, which must also use `try` or `catch`; top-level `try` reports an unhandled failure and exits nonzero. Multiple uncaught families in one word are rejected; handle a failure or explicitly wrap it as common `Error`. `catch [name]` handles a failed Result with a same-typed fallback, written as an indented block or as a single expression on the same line (`text.to-int("x") catch 0`; a lone name directly before the newline stays the block form's error binding); `console.exit(status)` or `console.fail(message)` may terminate instead of producing the fallback value. `console.fail` writes a line to stderr and exits 1 without a diagnostic. Explicit `Result<T, E>` signatures remain supported with `ok(value)`/`err(error)` and do not wrap successful results twice. Results cannot be discarded: a Result stored by `let` must be handled in the immediately next statement in the same block, as a standalone `name try`/`name catch` expression or the full right-hand side of a new `let`; it cannot be aliased or deferred.
- Error inspection/reporting: `error.new` and `error.wrap` create common Error values; `error.code`, `message`, `operation`, `file`, `line`, `column`, and `detail` inspect them; `error.has-cause` and `error.cause` inspect causes. A caught concrete-family error can go directly to built-in `error.*` operations, but must be wrapped before passing to a user word that accepts `Error` or storing it in an `Error` field/collection. Pass the wrapped value in a direct named call; a flow cannot pass an Error into a user-defined step. Install a named `(Error) -> Unit` reporter with top-level `error.set-reporter`; call `error.report` for a handled failure. Unhandled failures invoke it once before the normal diagnostic; propagation does not. Valid deliberate `console.exit` and `console.fail` do not invoke it; an invalid exit status is a runtime diagnostic and does. Reporter calls to either operation cannot replace the original outcome. There is no external reporter destination by default.
- Input: `read-line(prompt)` returns `Result<String, InputError>` and `text.to-int(text)` returns `Result<Int, ParseError>`. Handle failures with `try` or `catch`; at end of input `read-line` fails with `reason` detail `end-of-file` (read with `error.detail`), and a genuine read failure carries `read-failed`. Program arguments come from `console.arg(i)` (a `Result`) and `console.args-count()`, forwarded by `zhex run <file> [args...]`.
- Standard operations: `ok`, `err`, `print`, `range`, `int.to-string`, `read-line`; `text.` words — `to-int`, `reverse`, `length`, `line-count`, `word-count`, `upper`, `lower`, `trim`, `contains`, `index-of`, `slice`, `replace`, `split`, `join`, `starts-with`, `ends-with`; `list.` words — `new`, `length`, `append`, `map(values, transform)`, `filter(values, predicate)`, `select(values, predicate)` (true keeps the element, unmodified; arrays select whole rank-2 rows passed as `List<T>`), `fold(values, initial, step)`, `find(values, predicate)`, `any(values, predicate)`, `all(values, predicate)`, `sort(values)`, `sort-by(values, key)` — callbacks are ordinary function values (partials, no lambda syntax), `find` returns `Option.Some(first match)` or `Option.None`, `any`/`all` return `Bool`, and `sort`/`sort-by` return stable ascending copies: `sort` accepts `List<Int>`/`List<String>`, `sort-by` ranks any list by an Int or String key evaluated once per element in source order (code-point string order, fresh outer list, shared elements, source unchanged); `array.` words — `new`, `shape`, `rank`, `length`, `resize`, `select(values, predicate)` (rank-2 rows as `List<T>`, rectangle preserved); `map.` words — `length`, `contains`, `remove`, `put`, `into`; map lookup returns built-in `Option.Some(value)` or `Option.None`; `json.decode` and `json.encode` handle supported typed values; `xml.decode(text, defaults)` decodes XML documents into typed records the same way (attributes map onto record fields verbatim, a collision with a child element name fails, repeated elements become `List<T>`, absent elements fall back to defaults or `Option<T>`, unknown elements and namespace-prefixed names are rejected, DTDs and undefined entities fail, depth 256); `json.parse(raw)` returns `Result<Json, Error>` as a host-owned recursive tree (`Null`, `Bool(value)`, `Text(value)`, `Number(literal: String)`, `List(values: List<Json>)`, `Object(fields: Map<String, Json>)`) that `json.encode` also accepts — trees are ordinary data (constructible, storable in records, matched with plain `match`), round trips preserve key order and number literals byte-for-byte with compact whitespace, `Json.Number` literals are validated against the JSON number grammar at encode, recursion stays host-only (user records may hold a `Json` field), and JSON depth 256 plus word-call depth 256 put a recursive word over a maximally deep tree exactly at the call-depth edge; temporal operations use `date.`, `time.`, `duration.`, `instant.`, `timezone.`, and `zoned.` namespaces (see the temporal guide); `buffer.` words — `new`, `add-line`, `line-count`, `line`, `set-line`, `to-text`; `file.` words — `read`, `open`, `read-line`, `close`, `write` (contents, path, append = false), `stream` (loops only), `list` (sorted bare entry names, dot entries included, fresh list, 1,000,000-element limit), `exists` (plain `Bool`; not-found is `false`, other stat failures are runtime diagnostics, and `try`/`catch` selects the checked `Result<Bool, FileError>`), `size` (regular-file bytes, directories 0), `free-space` (bytes available on the volume of any existing path), plus the pure lexical path words — `join` (concatenate with the native separator and clean; an absolute child replaces the base), `base` (final element), `extension` (final-dot suffix of the final element, dot included), `directory-of` (all but the final element) — all plain `String` with no filesystem access; plus the destructive words — `make-folder` (one level; `parents = true` creates ancestors and tolerates an existing folder), `delete` (a file or an empty folder), `delete-folder` (empty folder; `recursive = true` removes the tree best-effort, first failure reported), `move` (rename-based, files and folders; `overwrite = true` replaces an existing file only, folder targets are refused, cross-device fails with no copy fallback); `console.arg`, `console.args-count`, `console.exit`, `console.fail`; `env.` words — `get(name)` (total `Option<String>`: an unset name is `Option.None`, set-but-empty is `Option.Some("")`), `load(path = ".env")` (`Result<Unit, Error>` reading KEY=VALUE lines into the process environment; first assignment wins — a key already in the environment or set by an earlier line is never overridden; blank lines and whole-line `#` comments are skipped, surrounding quotes on the value are stripped, a read failure fails `env-read` and a malformed line `env-parse` naming the line number, and lines before a malformed one stay applied); `error.` words — `set-reporter`, `report`, `new`, `wrap`, `has-cause`, `cause`, `code`, `message`, `operation`, `file`, `line`, `column`, `detail`.
- Modules: `use math` imports the sibling `math.zhex` next to the importing file; the REPL resolves against the working directory and adopts the module for the session. Imported words are called qualified (`math.gcd`) and call each other bare inside their own file; a leading underscore makes a word or type private to its module. Public signatures, record fields, and choice payloads cannot expose a module-private type, including through `List`, `Array`, `Map`, or `Result`. Imported choices use qualified type and alternative names (`model.Status.Pending`). `use` is a reserved word, top-level only; missing files, cycles, and reserved module names (`text`, `int`, `buffer`, `file`, `console`, `error`, `list`, `array`, `map`, `json`, `xml`, `date`, `time`, `duration`, `instant`, `timezone`, `zoned`, `env`) diagnose with the searched path. The built-in `Option` type and its `Some`/`None` constructors are reserved names.
- Names: ASCII letters, digits, underscores, plus hyphenated segments (`is-palindrome`). Dots qualify operation names (`int.to-string`, `math.gcd`); a dot names the type or module that owns the word. A dot after a bound record value reads a field (`customer.name`); nested field paths are allowed. A leading underscore marks a word or type module-private. Gotcha: `a-b` is a single name — write `a - b` for subtraction.
- Buffers and files: `let` binds a `Buffer` or `File` name, not a copy — two names observe one buffer. Both are excluded from `==`/`!=` and rejected by `print` (turn a buffer into text with `buffer.to-text`); the buffer, file, input, argument, and error-cause words that can fail return `Result`s handled with `try` or `catch`.

REPL sessions: `zhex repl [--trace]` keeps words and values across entries. Calls keep parentheses and may use the simple comma-separated form (`print 1 + 1`) at complete expression boundaries. A bare word name calls an accessible zero-argument word, including `bye`. On an interactive terminal, pending blocks prefill editable indentation; Tab inserts four spaces, Backspace removes one character; four presses dedent one level. An empty or spaces-only continuation line submits, except that blank and comment-only lines inside open `()`, `[]`, or `{}` delimiters keep the entry open. Closing a completed top-level expression submits it immediately; a pending block still needs a blank line. While editing, Ctrl-C cancels the current entry; Ctrl-D on an empty top-level prompt exits 0; in a pending entry, an empty or spaces-only continuation line discards the entry and exits. Bracketed paste preserves source indentation. Piped entries keep the existing line-based behavior and need explicit four-space indentation; tabs and non-ASCII whitespace outside strings or comments remain source errors. An unclosed delimiter at piped EOF is a syntax error. Program `read-line` input uses the terminal reader without source auto-indentation or Tab expansion. A blank line ends a multi-line entry when no delimiter is open; only a missing indented block or an open delimiter continues it. A comment-only line never completes an entry — it joins the next line's entry, so a `##` doc block shares its entry with the word it documents, and `words` typed right after a comment line still runs the command. Redefining a word with the same effective signature replaces it and prints `redefined <name>`; an incompatible inferred-signature change is rejected transactionally, and `let` shadows silently. `words` lists effective parameter, return, and Result signatures — a module's words are qualified after `use math` adopts it for the session, and a documented word's `##` doc prints indented beneath its signature — and bare ordinary expressions echo their value; naked Results must be handled with `try` or `catch` in the same entry. Errors print the annotated diagnostic and the session survives; a runtime error keeps the entry's earlier effects. A final line without its newline still runs. The preloaded ordinary REPL word `bye() -> Unit` exits with status 0, appears in `words`, and follows normal redefinition rules; it is unavailable in source files. The `words` command shadows a user binding of that name.

Canonical patterns live in `examples/` — `gcd` shows recursion and a flow seeded with a computed call, `choices` declares alternatives and handles them with a match, `times-table` shows bounded loops and string building, `life` updates a finite grid generation by generation, `edit-distance` fills a dynamic-programming table, `collatz` counts steps with a `while` loop, `json-tree` parses a heterogeneous payload into a `Json` tree and walks it recursively, `text-stats` reads a file two ways (whole-file counts and a streamed uppercased echo) as the first real application, `xml-config` decodes an embedded XML document with attribute fields and a list of endpoint records, and `paths` composes and decomposes paths lexically, `file-work` builds a work folder, inspects it, and removes the tree, `env-config` writes a `.env` fixture, loads it, and reads each setting back as an Option match, and `modules/md-report` renders records and lists into a Markdown report through the pure-Zhex `md` module, and `modules/html-page` composes an HTML page from the `html` module (text escaped by default, `html.raw` the documented bypass, `html.link` rejecting every scheme besides relative, http, https, and mailto), and `modules/math.test` checks the math module from a `*.test.zhex` file through the one-word `test` module's `check` (the `zhex test` seed) — and on the website's examples page (desireco.github.io/zhex/examples.html).

## Reading checker errors

The checker validates the whole program before anything runs and reports `file:line:column` diagnostics, so nothing partial executes. Each diagnostic prints the source line with a caret — the caret underlines the whole failing expression, not one column — and, where a known fix exists, a `hint:` line; the first line stays stable for scripts and agents. Type mismatches narrate where a value came from, e.g. `...found Result<Int, ParseError>; m comes from text.to-int`. The mistakes the compiler now hints itself:

- `unknown name "a-b"` — hyphenated names are single names; write `a - b` with spaces for subtraction.
- `... does not support type Result<String, InputError>` (or any `Result` in a plain value position) — handle it with postfix `try` or `catch` (`let line = read-line("N: ") try`). A bare fallible call is rejected; a Result stored with `let` must be handled immediately in the same block.
- `print does not support type Buffer` — a buffer is lines, not text; convert it first (`print(buffer.to-text(b))`).

Typos get did-you-mean suggestions drawn from the visible names and words. Hint voice: literal and specific — the message states the problem as fact, the hint names an action; no metaphors, no gestures, never terminology implying a keyword that does not exist (the contract's rule 5). Built-in diagnostics carry stable codes cataloged on the site's errors page; application codes passed to `error.new` and `error.wrap` are owned by the application and do not appear in that catalog. `zhex run <file> --report=json` emits the machine-readable report `{code, severity, file, line, column, message, hint}` for agents and tools, plus optional additive `span_start_column`/`span_end_column` — present only for checker diagnostics with a span, never for runtime ones. The diagnostic contract and phased plan (spans, provenance, tracing, replay) live in `docs/diagnostics-plan.md`, which supersedes the channel sketches in `docs/error-reporting-research.md` and older tickets.

`zhex run <file> --trace` watches a run instead of its failures: it streams JSONL step events to stderr — word calls with rendered arguments, binding writes with values, flow steps, and word returns — before any diagnostic, and combines with `--report=json` (events, then the report). Agents: use it to see what a program did; the event vocabulary is documented in the site's llms.txt. Tracing never fails a run, and output without the flag is unchanged.

To validate a program quickly, run `go run ./cmd/zhex run <file>` — checking happens before execution, so a clean run means types and names resolved. `zhex doctests <file>` runs the `## >` examples in word docs: the expression evaluates in the owning module's scope, the expected output is the doc lines after the `## >` line until a blank doc line or the next `## >` line ends them (a blank line returns the doc to prose; prose directly after an example reads as output and mismatches) compared with the value as the REPL echoes it, and plain `zhex run` never executes docs. `zhex test [path]` runs every `*.test.zhex` file under the working folder (or the given file/folder, skipping `.git`, `node_modules`, `_site`) as its own process — its exit code is the whole contract — plus every other `.zhex` file's doctests: one PASS/FAIL line per file with the captured failure line, a summary (`N files: X passed, Y failed`), exit 1 on any failure, `--report=json` failures in the diagnostic envelope (a plain failed check reports `test-failed`), and `--gaps` listing public words referenced by no doctest and no test file. A test file is a plain program that calls `test.check(condition, label)` from the sibling `test` module (a false condition fails the run with its label); `just doctests` runs `bin/zhex test examples` with one built binary and joins `just test`, seeded by `examples/modules/math.test.zhex`.

## Ticket workflow

File every new ticket into the board's **Inbox** bucket with no status — never straight into Todo; triage promotes Inbox cards. Work on tracked tickets (issues on the project board) in this order:

1. **Analyze first.** Read the ticket and study the relevant code or docs. If the ticket is unclear or incomplete, improve it: update its title and description so it states the goal, scope, and acceptance criteria accurately.
2. **Claim before working.** Post your plan as a comment, then move the card to In Progress. A ticket must be In Progress while anyone is working on it, so nobody else starts the same work; if nobody has claimed it, claim it before you start.
3. **Follow the plan** until every part of it is done; keep scope to what the ticket describes.
4. **Return unfinished tickets.** If you cannot complete the ticket, stop, leave a comment with what is done and what remains, and move the card back to Todo. Never leave a ticket In Progress unattended.
5. **Verify and record.** Make the functionality work (tests, build, deploy checks), then update everything that records truth wherever it lives: website docs, repository docs, AGENTS.md, ROADMAP.md, and the board. A new word, signature change, or rename/removal follows the checklist in `docs/vocabulary-checklist.md` — every surface from interpreter sync points to editors and truth surfaces, tests first.
6. **Close last.** A green build on the branch moves the card to Done and closes the issue with a short ship note. Pushing never gates ticket status; work ships when the arc merges.

## Verifying work

- `just test` must pass for any change — it covers the interpreter, examples, and website build; `go vet ./...` must be clean.
- `just bench` measures the interpreter with allocation counts; results and method live in `docs/measurements.md`.
- Tests are the language definition: extend them test-first when changing behavior, and keep `ROADMAP.md`'s Done/Next/Future shape (the website generator validates it).
- Run a program with `go run ./cmd/zhex run examples/hello.zhex`; build the website with `just site` (the site build compiles the examples' browser wasm artifacts, so `just site` and `just test` need the wasm-tools assembler — one-line installs on the website's compiling page; a missing install fails the build loudly with those hints). User-facing surfaces (website pages, llms.txt) show the canonical `zhex run examples/<file>.zhex` and `zhex compile examples/<file>.zhex` forms instead — the getting-started pages teach installing Git and Go and building the binary once with `go build -o bin/zhex ./cmd/zhex` (`bin\zhex.exe` on Windows), and `just build` runs the same recipe for development. Changes that touch the WebAssembly compiler also run `just corpus`.
- Commits are focused and conventional (`feat:`, `fix:`, `docs:`, `chore:`), made on `main`.
