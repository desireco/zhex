Zhex design system · Version 1

Small words.
Big ideas.

This system gives Zhex one visual and verbal language across the brand, website, documentation, and code examples. It is designed for contributors who need to explain the language clearly without making compactness feel cryptic.

01 · Foundation

Clarity through composition.

Modular

Pages, components, and messages are built from small reusable parts—just like Zhex programs.

Explicit

Hierarchy, state, links, and data flow remain visible. Decoration never hides structure.

Direct

Copy is concise, typography is confident, and orange marks the next useful action.

DirectionFunctional editorial: warm neutral ground, black structural typography, and signal orange used with restraint.
PromiseCompact ideas remain understandable as they compose into larger programs.
MottoSmall words. Big ideas.

02 · Logo

The symbol explains the language.

ZThe prominent modular letter represents small words joining into a recognizable whole.
ChevronThe prompt shape represents execution, explicit flow, and ideas moving forward.
hexThe lowercase name stays quiet so the symbol leads while the complete wordmark remains readable.

Maintain clear space equal to the chevron tile on every side. Do not rotate, stretch, recolor individual strokes, or place the light logo on a low-contrast background.

03 · Color

Orange signals meaning.

Paper#F6F3EC · page ground
Ink#1D1B19 · text and code
Signal orange#FF5A2A · actions and emphasis
Surface#EBE6DC · secondary fields
Orange soft#FFD8CC · state halos
Focus blue#1541C6 · keyboard focus

Use orange for selected phrases, action states, progress, and syntax—not as the default page background. A surface should usually contain one dominant orange signal.

04 · Typography

Large ideas, readable details.

Display

Small words.

Body

Zhex keeps compact code understandable through visible flow, meaningful names, and checked types.

Monospace

flow name → greet → print

Use display type for one main idea at a time. Body copy stays between 65 and 76 characters per line. Monospace is reserved for code, labels, status, and technical metadata.

08 · Content voice

Explain first. Impress second.

Concrete

Say what the language does: “flow passes each result forward.” Avoid abstract claims without examples.

Compact

Prefer short sentences and visible structure. Remove repeated value propositions.

Honest

Call the interpreter experimental, label private access, and separate current behavior from future plans.

HeadlineOne memorable idea: “Small words. Big ideas.”
SupportExplain the practical value in one sentence.
EvidenceShow real code, output, examples, or roadmap status.

09 · Accessibility

Clarity must work for everyone.

  • Body text remains at least 16px with a 1.5–1.75 line height.
  • Orange is paired with text, shape, or position; it never carries meaning alone.
  • Every interactive element has a visible keyboard focus state and a descriptive label.
  • Large headlines wrap at words, not arbitrary characters.
  • Code and tables scroll horizontally instead of clipping on narrow screens.
  • Reduced-motion preferences remove nonessential transitions.

10 · Release checklist

Before a Zhex page ships.

  1. Lead with one clear message and remove repeated explanations.
  2. Use tokens rather than introducing one-off colors or spacing values.
  3. Link every element that visually promises interaction.
  4. Show real Zhex syntax and preserve source fidelity.
  5. Label experimental, planned, private, or unavailable behavior honestly.
  6. Check keyboard navigation, mobile reading, code overflow, and reduced motion.
