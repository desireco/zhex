# Zhex roadmap

Build a readable language from small, composable words. The Go interpreter lets us try the syntax and settle behavior before choosing a compiled implementation.

## Done

The first language milestone runs real programs with checked types and console input and output.

- Interpreter: typed words, inferred locals, conditions, bounded loops, and checked flows.
- Working examples: composition, console input, FizzBuzz, Fibonacci, factorial, palindrome checking, a recursive GCD, and a times table.
- Executable specification: tests cover syntax, types, scope, arithmetic boundaries, Unicode, and failure paths.
- Getting started: documentation, a public examples website, just recipes for development, and local highlighting packages for Vim/Neovim, VS Code, and Zed.
- Website: Astro-powered topic documentation and an editorial redesign with a new logo, syntax-highlighted examples, and a published design system with a concept archive.
- Licensing: the repository is public and published under the MIT license.
- Editors: syntax highlighting for Vim/Neovim, VS Code, and Zed, with installation and usage documented on the website's docs page.
- Agents: AGENTS.md, an llms.txt site index, and agent-readable examples make Zhex easy for humans to review and AI agents to write.
- Errors: built-in diagnostics point at the source, carry stable cataloged codes, and can report as JSON; user words declare success types and infer a single escaping Result family through `try`, then callers propagate with `try` or recover lazily with `catch`. Multiple uncaught families are rejected; explicit `Result<T, E>` signatures remain supported. Results cannot be silently discarded. Structured Error values expose code, origin, details, and causes; a named reporter can observe explicit handled reports and each unhandled terminal failure without external delivery by default. `console.exit` provides deliberate statuses from 0 to 255; `console.fail` writes a message to stderr and exits with status 1. Both close active `file.stream` loops on termination.
- Input: `read-line`, `text.to-int`, file, buffer, and argument reads return explicit Results. Callers choose a fallback with `catch`, propagate through compatible fallible words with `try`, or let the program boundary report an unhandled failure.
- Insight: `zhex run --trace` streams JSONL step events — word calls, bindings, flow steps, returns — so people and agents can watch a program run; the event vocabulary is documented in llms.txt.
- REPL: `zhex repl` keeps words and values across entries, enters multiline blocks and delimited expressions with editable terminal auto-indentation, four-space Tab and bracketed paste support, echoes expression values, redefines words with a note, lists signatures with `words`, recovers from errors, and traces with `--trace`.
- Vocabulary: rich text work ships — sixteen `text` words, with literal split, join, and prefix/suffix checks added by the first standard-library story (#57), `Buffer` and `File` types, guaranteed-close `file.stream` loops, whole-file reads through `file.read`, checked report output through `file.write` with the first built-in trailing constant default (#58), and program arguments via `console.arg`.
- Vocabulary: collection composition ships — `list.map`, `list.filter`, and `list.fold` run ordinary function-value callbacks (explicit or word-name partials, no lambda syntax) once per element left to right, with fresh outer lists, shared elements, an unchanged source, and the traversal guard held throughout (#60), and `list.find`, `list.any`, and `list.all` short-circuit over the same callback contract, with `find` returning `Option.Some` or `Option.None` (#61); Result-returning callbacks and Result fold accumulators are rejected, and the registered `score-report` example demonstrates all six words.
- Vocabulary: deterministic ordering ships — `list.sort` returns a stable ascending copy of `List<Int>`/`List<String>` values in code-point string order, and `list.sort-by` ranks any list by an Int or String key callback evaluated once per element in source order under the traversal guard (#62); both return fresh outer lists with shared elements and unchanged sources, equal keys keep source order, and the registered `sorting` example demonstrates both words.
- Vocabulary: file inspection ships — `file.list(folder)` returns one level of a folder's bare entry names, dot entries included, as a fresh sorted `List<String>` inside a `Result` under the shared million-element limit, `file.exists(path)` answers existence as a plain `Bool` where a missing path is `false` (postfix `try`/`catch` selects the checked `Result<Bool, FileError>` form), and `file.size(path)` and `file.free-space(path)` report a regular file's bytes and the bytes available on a path's volume inside Results (#73); failures carry the stable codes `file-list`, `file-exists`, `file-size`, and `file-free-space`, and the executable example was deferred until `file.make-folder` made a deterministic one possible.
- Vocabulary: lexical path words ship — `file.join(base, child)` concatenates with the native separator and cleans, with an absolute child replacing the base (`file.join("a/b", "/c")` → `/c`) so untrusted absolute components never nest under a base; `file.base(path)`, `file.extension(path)`, and `file.directory-of(path)` decompose a path into its final element, final-dot suffix (dot included, `.bashrc` for the dotfile), and everything but the final element (#74); all four are pure `String` words with no filesystem access, and the registered `paths` example demonstrates them.
- Vocabulary: destructive file operations ship — `file.make-folder(path, parents = false)` creates one folder level or, with `parents = true`, every missing ancestor while tolerating an existing folder, `file.delete(path)` removes a file or an empty folder and refuses a nonempty one, `file.delete-folder(path, recursive = false)` removes an empty folder or, with a deliberate `recursive = true`, the whole tree best-effort (part may be gone before the first failure), and `file.move(source, target, overwrite = false)` renames files and folders, replaces an existing file only with `overwrite = true`, refuses folder targets in both modes, and fails cross-device moves with the platform's error (#75); the mode arguments are built-in trailing constant defaults, failures carry the stable codes `file-make-folder`, `file-delete`, `file-delete-folder`, and `file-move`, and the registered `file-work` example pays #73's deferred-example debt with a deterministic make-folder → write → list → size → free-space → delete round trip.
- Vocabulary: JSON heterogeneous trees ship — `json.parse(raw)` returns `Result<Json, Error>` over `Json`, a host-predeclared recursive choice (`Null`, `Bool`, `Text`, `Number(literal)`, `List`, `Object`) that programs never declare; trees are ordinary data — constructible, storable in records, matched with plain `match` — while recursion stays host-only (#76). `json.encode` accepts trees: `encode(parse(raw))` preserves key order and number literals byte-for-byte and normalizes whitespace to compact; `Json.Number` literals are validated against the JSON number grammar at encode, strictness (duplicate keys, depth 256, the million-element cap, UTF-8/surrogates, JSON Pointer paths) is shared with `json.decode` with no new codes, and JSON depth 256 plus word-call depth 256 put a recursive word over a maximally deep tree exactly at the call-depth edge. The registered `json-tree` example counts a heterogeneous payload recursively and round-trips it.
- Vocabulary: predicate selection ships — `list.select(values, predicate)` keeps the elements a `(T) -> Bool` predicate accepts, unmodified, and `array.select(values, predicate)` keeps whole rows of a rank-2 array, passing each row to the predicate as a fresh `List<T>` and preserving the rectangle (#70); both follow the #60 callback contract, visit every element or row without short-circuiting, return fresh outer collections with shared elements and unchanged sources, reject Result-returning predicates at check time, and rank 3+ arrays report `array.select requires a rank-2 array` at runtime; the updated `collections` example demonstrates both words.
- Language: indefinite iteration and distinguishable EOF ship — `while condition` repeats an indented body while its `Bool` condition holds, evaluated before each pass; it is a statement of type `Unit`, is rejected as a binding or assignment right-hand side, has no `break`/`continue`, and may run forever by design with no iteration limit, and `read-line` keeps its `Result<String, InputError>` shape while its end-of-input failure carries a `reason` detail of `end-of-file` versus `read-failed` for a read failure, read with `error.detail` (#72); both land as #65's prerequisites, and the registered `collatz` example demonstrates the loop.
- Language: the string-context Int exception ships — `+` concatenates when exactly one operand is `Int` and the other is `String` (the Int renders as `int.to-string` does, chains associate left to right, and two `Int` operands still add numerically), and `print` accepts an `Int` directly (#83); `Bool` and every other type stay strict in these positions, and the no-implicit-conversions law keeps every other position strict.
- Vocabulary: typed XML decode ships — `xml.decode(text, defaults)` returns `Result<T, Error>`, schema-directed exactly like `json.decode` over the same supported types on the stdlib encoding/xml tokenizer (#79); attributes map onto record fields verbatim with a collision failing the decode, repeated same-named elements collect into `List<T>`, absent elements use defaults or `Option<T>` (no null marker), text-only elements decode as `String`/exact-integer `Int`/`true`|`false` `Bool`, and strictness rejects unknown elements and attributes, mixed content, namespace-prefixed or `xmlns`-resolved names, DTD/entity declarations, and undefined entities, with predefined and numeric entities decoded and no network ever; limits mirror JSON (depth 256, one million elements) and failures carry `xml-syntax`, `xml-type`, `xml-field`, `xml-range`, and `xml-depth` with element paths. The registered `xml-config` example decodes an embedded service configuration.
- Vocabulary: environment configuration ships — `env.get(name)` answers the process environment as a total `Option<String>` (an unset name is `Option.None`, a set-but-empty name is `Option.Some("")`) and `env.load(path = ".env")` reads KEY=VALUE lines into the environment inside `Result<Unit, Error>`, common-Error family like `json.parse`, with first assignment wins — a key already in the environment, or set by an earlier line of the same file, is never overridden (#64, the environment half; the path words shipped as #74); blank lines and whole-line `#` comments are skipped after leading trim, one matching pair of surrounding single or double quotes on the value is stripped, `KEY=` sets the empty string, a malformed line fails `env-parse` naming the line number and a read failure `env-read` with lines before a malformed one staying applied, the `.env` trailing constant default stays deferred for partials like `file.write`'s `append`, and `env` joins the reserved module names; the registered `env-config` example demonstrates both words.
- Language: word doc comments ship — a contiguous block of full-line `##` comments at column 1 directly above a `word` declaration becomes that word's doc, with one optional leading space stripped per line, lines joined with newlines, and a blank line or plain `#` comment detaching the block while `##` anywhere else stays a plain comment (#93); `words` prints the doc indented four spaces beneath the signature (a blank doc line renders empty, module words qualified), docs live on the word so a redefinition replaces or clears one without affecting signature compatibility, user words only — records, choices, and built-ins get none — and a REPL comment-only line now joins the next line's entry, so a doc block shares its entry with the word it documents while `words` typed after a comment line still runs.
- Tooling: doctests ship — a doc line of the form `## > expression` is a doctest whose expected output is the doc lines that follow until a blank doc line, the next `## >` line, or the doc's end (a blank line returns the doc to prose; prose directly after an example reads as output and mismatches), and `zhex doctests <file.zhex> [--report=text|json]` compiles the file like a run without executing its body, then checks and evaluates each documented word's examples in the owning module's scope (bare calls resolve inside the module), comparing the REPL echo of the value with the expected lines (#94); a mismatch or an expression that fails to check or evaluate is a diagnostic pointing at the doc line with the stable codes `doctest-mismatch` and `doctest-check` in the catalog and `--report=json`, any failure exits nonzero, a bare `Result` stays rejected so fallible examples use `try`, passing runs print nothing, and plain `zhex run` never executes docs; `just doctests` sweeps every example with one built binary as part of `just test`, seeded on every public word of `examples/modules/math.zhex` (md and html deferred).
- Rich values: explicit binding annotations, nominal records with named constructor arguments and optional field defaults, block-valued bindings, transparent type aliases, and one-parameter choices with exhaustive matching, homogeneous shared `List<T>` and shaped `Array<T>` collections, inferred `Map<K, V>` with built-in `Option<V>` lookup, plain list/array reads and mutations with optional checked forms, insertion-ordered map operations, and collection traversal with bindings and mutation guards. Typed JSON decoding with explicit record defaults and encoding for the supported value subset is also available. Dates, times, durations, instants, and named zones support calendar and elapsed-time operations.
- Text utility: `text-stats` reads a file two ways — whole-buffer counts and a streamed uppercased echo — with program arguments, streamed lines, and guaranteed close, all through the new vocabulary (#28) — and becomes the workload for measurements (#4).
- Measurements: the interpreter runs text-stats at 8-9 ms per pass with stable allocation profiles by mode (docs/measurements.md); readability review recommends a line-filter tool as the next application, with number-to-text ceremony flagged for a future language story.
- Tools: the line-filter tool ships as the first end-to-end application — `zhex run examples/filter.zhex <pattern> <file>` prints matching lines verbatim, streaming the file; wrong arguments fail with a usage line and a missing file reports its natural FileError (#81).
- Modules: `use math` loads sibling files, words are importable unless underscore-private, calls are qualified, cycles and reserved names diagnose with paths, and the REPL adopts modules per session — with a two-file corpus example and docs sections to match.
- Modules: the pure-Zhex `md` Markdown report module ships as a validated sibling module beside a two-file `md-report` example (#77) — fragment-returning words (heading, paragraph, bullet/ordered lists, link, fenced code block, tables added by owner decision), per-position escaping with `max(3, longest run + 1)` fences, percent-encoded link targets that neutralize `javascript:`/`data:` schemes, strict header-width table rows, and verbatim paragraphs; the example composes records and lists into a buffer and prints, with no host words or editor changes.
- Modules: the html composition module ships (#78) — a pure-Zhex sibling module with the guarantee "escaped unless raw": `html.escape-text` pins Go `html.EscapeString` semantics over `&`, `<`, `>`, `'`, `"` (stays in the module; no second workload justified host promotion), `html.attr(name, value)` builds one pre-escaped attribute and `html.element(tag, attributes: List<String>, content)` joins them with text escaping left to `escape-text`, `html.page` emits the doctype document with an escaped title, `html.raw` is the identity bypass documented against every escaping property, and `html.link` allows only relative, `http`, `https`, and `mailto` targets, rejecting every other scheme (including `javascript:` and `data:`) with the `html-url-scheme` code; the registered `modules/html-page` example composes a page and one rejected link.

## Next

Grow the language's reach: a dedicated domain and funding. This is the proposed order; each step needs working examples and tests.

- Standard library: the read-API rename and folder research are done (#68/#69), and the folder-operations stories all shipped — file inspection (#73), lexical path words (#74), and destructive operations (#75) — with editor keyword sync (#71) shipped with its drift-prevention test, the JSON tree type and `json.parse` shipped from the document research (#76), and the XML typed decode shipped as #79, with #64's environment half (`env.get`, `env.load`) joining them and its path words already in #74; predicate `select` for lists and arrays (#70) shipped from the owner interview, leaving the Markdown research (#67) queued in Todo, and the #65 language prerequisites — the `while` loop and `read-line`'s EOF `reason` detail — shipped (#72). #57's literal text operations, #58's `file.write`, #59's edit-distance simplification, #60/#61's list callback words, and #62's list sorting shipped. The six-language research and dependency order live in `docs/standard-library-plan.md` (#30); proposed operations are not shipped.
- Domain: buy a dedicated domain for the language and point it at the published site.
- Funding: enable GitHub Sponsors or Open Collective with a sponsor section on the site, and pursue the researched grant and visibility channels (#26).

## Future

These are directions to explore. Their order and implementation remain open, and there are no delivery dates yet.

- Dogfooding: investigate a Zhex-written REPL front end over the Go session engine (#65), beginning with a bounded prototype and explicit host/input boundaries; full interpreter self-hosting is not in scope.
- Rich values: generic records and words, and user-defined error types with readable operations and formatting.
- Compiled execution: evaluate a native backend, including C as a possible target, and measure composition, text processing, and allocation behavior.
- WebAssembly code generation: compile Zhex programs to WASM, starting with browser execution and a small host interface for input and output (#7; findings, decisions, and milestone plan in docs/wasm-plan.md).
- Application libraries: grow through small CLI, HTML-processing, web-server, game, and database experiments.
- Development tools: formatting, language-server support, and published editor packages as the syntax settles.
- Development insight: record-and-replay runs, debug-adapter support, and agent tools, so people and AI agents can see and debug what a program is doing (see docs/diagnostics-plan.md).
- Module growth: exposure lists, import renames, subfolder paths, and computed module constants, composing on the simple use-and-underscore design when each earns its place.
