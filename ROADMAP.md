# Zhex roadmap

Build a readable language from small, composable words. The Go interpreter lets us try the syntax and settle behavior before choosing a compiled implementation.

## Done

- Vocabulary: the int bitwise words ship — `int.and(a, b)`, `int.or(a, b)`, and `int.xor(a, b)` are two's-complement bit operations over the target's full Int width (128-bit interpreter/native, 64-bit wasm/browser engine per the #178 ruling; values below 2^64 behave identically in all four targets), `int.shift-left(a, n)` is the mathematical a·2^n obeying the overflow law like every arithmetic operation (a count of 128 or more fails `integer overflow` for nonzero values on 128-bit targets — the owner's 2026-11-24 amendment superseded the proposed clamp-to-zero default), and `int.shift-right(a, n)` is the arithmetic sign-keeping floor(a/2^n) that never overflows (count past the width gives `0`, `-1` for negative values); 64-bit wasm/engine builds fence shift counts of 64 or more with `int-shift-width` before overflow can apply, even for a zero value, and a negative count fails `int-shift-count` in every build; plain `Int` results with no Result form (`catch` rejected as on division), partials work (`let mask = int.and _, 7`), `int.not` is deliberately absent (on the full width it is `-a - 1`), and words were chosen over `& | ^ << >>` so the grammar is untouched (#231, differential across interpreter, wasm, native, and the browser engine; no example per the #160 rule).
- Vocabulary: the list end words ship — `list.pop(values)` removes the last element and returns it (`T`, the one exception to mutation-returns-receiver), `list.first(values)` and `list.last(values)` read the ends returning `T` with the list unchanged, all three are checked collection operations (plain call yields `T`, `try`/`catch` selects `Result<T, Error>`), an empty list fails the stable `list-range` code like an out-of-range index, `list.pop` holds the iteration guard and its dropped element still pops on an ordinary line so a loop drains a stack, flows are the receiver form (`flow stack / list.append 4 / list.append 5 / list.pop` gives 5), and `list.remove-first` is deliberately absent — queues keep the head counter, and a head removal would move every element (#159, no new codes, no example per the #160 rule).
- Review: a second code review of the native target, the WebAssembly prelude, the new words, and the documents modules fixed, among others, a `try` flow step that native builds dropped silently, wrong accented text in PDF output (the PDF font now declares WinAnsiEncoding), an escaped pipe lost from a Markdown table row's last cell, and two programs that could hang — an unwalkable day 8 network now reports `the walk from AAA never reaches ZZZ` from a bounded walk check, and the browser engine no longer parks a delivery that arrives after the run finished; `text.repeat` and the pad pair fail their range codes past the runtime's allocation limit instead of crashing, the native depth diagnostic points at the call that made the 257th call like the interpreter, a Windows target builds a `.exe`, a native rebuild rewrites the copied runtime directory, and a new test fails when a co-located module copy drifts from its original.

- Modules: the pure-Zhex `diff` module ships — `diff.lines` computes the Myers O(ND) line diff between two texts as `Change.Keep`/`Delete`/`Insert` values (the per-round k-diagonal frontier kept as the trace, an iterative backtrack, loop-shaped with no recursion so diff size never meets the 256-call depth limit, CRLF normalized to LF and the split keeping the trailing empty entry after a final newline) and `diff.apply` replays them — the patch law `apply(diff(a, b) try, a) == b` with every Keep and Delete checked against the cursor, misalignment failing `diff-apply` instead of patching silently past the damage (#220); checked by `text-diff/diff.test.zhex` and demoed by `text-diff/main.zhex`.

- Modules: the md block operations and document stats ship — `md.insert-block`, `md.replace-block`, and `md.remove-block` edit at single-block grain (insertion points `0..block count` inclusive, `at` == count appends, the checked read channel naming a bad index), `md.set-blocks` replaces the whole block list, and `md.stats` folds the `Stats` record over a Doc — block-kind counts plus words and characters measured on each block's own text — with `md.section-stats` the per-section moment (#219).

- Modules: the md module exports HTML — `md.to-html` renders every block as escaped markup joined with single newlines (a run of one list kind as one nested `<ul>`/`<ol>`, a run of quote lines as one `<blockquote>` of `<p>` lines, code inside `<pre><code>` with the info string as the class attribute, tables as plain cells; inline spans are not parsed, so raw markdown links render as escaped text and `to-html` stays total), and `md.to-html-page` wraps the fragment in the full document with an escaped title (#209 fragment, #210 page; the escaping twin `_html-esc` is pinned byte-identical to the html module's `escape-text` in both modules' tests).

- Modules: the md module learns to read — `md.parse` turns Markdown text into the flat `Doc` in three slices (#203 headings, paragraphs, and rules; #204 bullet and ordered items and quotes with indent fields carrying the nesting; #205 fenced code blocks and pipe tables), `md.render` writes the Doc back through the write-side words joining blocks with blank lines (every parsed list is tight, loose lists tighten), `md.outline` lists every heading as a `Section` row (index, level, text) derived from the flat list, and `md.section`/`md.section-text` slice a section from a heading's block index with nested subsections riding along (#206); `md.remove-section`, `md.replace-section`, `md.insert-section`, `md.promote`, `md.demote`, and `md.move-section` edit by section with the checked read channel for bad indexes (#207); and the round-trip law — `render(parse(text)) == text` for canonical text, with the looser two-pass canonicalization law for any text whose rendered positions are punctuation-free — is pinned in md.test over a generated corpus (#208).
